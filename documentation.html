Subsidiaries Verification AI
Complete Technical & Setup Documentation

1. Full Technology Stack

This project utilizes a modern, async-first architecture to maximize scraping speed and minimize API bottlenecks.

  • Backend Framework: FastAPI (Python) with Uvicorn for high-performance asynchronous API endpoints and WebSockets.
  • AI Engine: Google Gemini Series via the google-genai SDK. The system utilizes a strict fallback architecture to guarantee high availability and prevent rate limits. The fallback sequence is:
    1. gemini-3.6-flash (Primary Engine)
    2. gemini-3.5-flash (Secondary Fallback)
    3. gemini-3.1-flash (Tertiary Fallback)
    4. gemini-3.5-flash-lite (Final Safety Fallback)
  • Web Search API: Serper.dev (Google Search API) for real-time indexing and Google Dorking.
  • Web Scraping Engine: Playwright (Async Headless Chromium) combined with BeautifulSoup4 to extract raw DOM text while bypassing basic JavaScript blocks.
  • Data Handling: openpyxl (for non-destructive Excel parsing and styling).
  • Caching Database: SQLite3 (Embedded local database to prevent redundant API calls).
  • Frontend UI: Vanilla HTML/CSS/JS, hosted optionally on GitHub Pages.
  • Data Visualization: vis-network (Physics-based Node Graph) and Chart.js (Donut charts).

Step 1: Excel Ingestion & Parsing

When the user uploads an .xlsx file, the backend loads it into memory using openpyxl. Unlike standard CSV parsers, this preserves the user's original colors, borders, and macros. The system automatically searches all sheet names for keywords like "LEM" or "legalentitymapping". Once the sheet is found, it dynamically scans the header row to locate the column containing the Entity Names (looking for headers like "entity", "company", or "account").

Step 2: Database Caching

Before executing any external API calls, the system queries the local SQLite cache (scan_cache table). It checks if the combination of (Parent_Company, Entity_Name) has been verified previously. If a cache hit occurs, the entity is instantly resolved and skipped, saving API credits and time.

Step 3: Multi-Source Scraping & Dorking (The "Scan Depth")

For uncached entities, the system searches the live web using an asyncio.Semaphore(4) queue to manage concurrency. The search behavior depends on the UI toggle:

  • Quick Scan: Fires a single query to Serper: "{Entity Name} {Parent Name}".
  • Deep Corporate Audit Advanced: Executes three parallel queries using Google Dorking:
    1. General Search: "{Entity} {Parent}"
    2. LinkedIn Dork: site:linkedin.com/company {Entity} {Parent}
    3. Crunchbase Dork: site:crunchbase.com {Entity} {Parent}

Playwright then physically visits the top URLs returned by Serper, extracts the <body> HTML, strips it using BeautifulSoup, and compiles a massive "Evidence String" for the AI.

Step 4: AI Forensic Analysis (Gemini 2.5 Flash)

The raw web evidence is bundled into chunks of 50 entities and sent to Gemini. The system prompt instructs Gemini to act as a Forensic Accountant applying the rule of Extreme Benefit of the Doubt (assume the user's spreadsheet is correct unless explicitly proven wrong by a competitor's website). Gemini outputs a strict JSON array containing:

  • is_match: Boolean (True/False)
  • confidence: String (High, Medium, Low)
  • evidence: Short snippet explaining the decision
  • source_link: The genuine URL where the evidence was found.

Step 5: Real-Time UI Broadcasting (WebSockets)

As the AI parses chunks and resolves entities, the FastAPI backend sends entity_result packets through an active WebSocket connection. The frontend Javascript intercepts these packets and uses Vis.js to dynamically pop new nodes onto the Corporate Network Graph in real-time (Green for Matches, Red for No Matches).

Step 6: Excel Generation & Export

Once all entities are processed, the backend maps the AI results back to the exact rows in the original Excel file. For entities marked is_match = False, the cell background is highlighted in Light Orange (Hex: #FFFFD580). Finally, the source_link is written into a new column and formatted using openpyxl's hyperlink styling, making the link natively clickable in Microsoft Excel. The file is then saved to the downloads/ folder and served to the user.

3. Setup Guide: How Others Can Run the Project

Prerequisites

You must have Python 3.10+ installed on your machine. You will also need API keys from two services:

  1. Google Gemini API Key: Get this from Google AI Studio.
  2. Serper API Key: Get this from Serper.dev (Free tier allows 2,500 searches).

Installation Steps

# 1. Clone the repository or navigate to the project folder
cd "Subsidiaries verification"

# 2. Create and activate a virtual environment
python -m venv venv
# On Windows:
.\venv\Scripts\activate
# On Mac/Linux:
source venv/bin/activate

# 3. Install required Python packages
pip install fastapi uvicorn google-genai playwright beautifulsoup4 openpyxl pandas requests python-multipart

# 4. Install Playwright browsers (Required for web scraping)
playwright install chromium

Configuring API Keys

In the backend/ folder, create a file named .env and add your API keys:

GEMINI_API_KEY=your_gemini_api_key_here
SERPER_API_KEY=your_serper_api_key_here

Running the Application

Execute the following command from inside the backend/ folder:

python main.py

The FastAPI server will boot up and automatically host the frontend UI. Open your web browser and go to:

http://127.0.0.1:8000/
