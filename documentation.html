2. Data Ingestion & Non-Destructive Parsing

Standard CSV parsers destroy corporate macros, formulas, and visual formatting. To resolve this, the backend leverages openpyxl to load the entire Excel workbook directly into RAM. The parser engine algorithmically searches for the target worksheet by applying regex heuristics to sheet names (targeting permutations of LEM and legalentitymapping).

Once isolated, the ingestion engine scans the header row to dynamically locate the primary index column (Entity Name). This allows the tool to be completely agnostic to the specific template structure provided by the end-user.

3. Anti-Bot Evasion & Parallel Dorking Strategy

Directly extracting corporate data from enterprise registries (such as LinkedIn and Crunchbase) is notoriously difficult due to advanced anti-scraping firewalls (e.g., Cloudflare, DataDome). The Deep Corporate Audit mode circumvents these firewalls entirely via a technique known as Google Dorking.

The Parallel Extraction Algorithm

When the system encounters an uncached entity, the backend spawns three concurrent async tasks utilizing an asyncio.Semaphore(4) buffer to regulate rate limits. The three parallel queries are:

  1. General Reconnaissance: "{Entity Name} {Parent Name}" — Extracts PR releases and financial news.
  2. LinkedIn Dork: site:linkedin.com/company "{Entity Name}" "{Parent Name}" — Forces Google's raw, unfiltered index to hand over the official LinkedIn corporate page data, bypassing LinkedIn's aggressive login walls.
  3. Crunchbase Dork: site:crunchbase.com "{Entity Name}" "{Parent Name}" — Extracts definitive startup acquisition histories, Series funding details, and parent portfolios.

The system aggregates the top 5 distinct URLs from these parallel results. Playwright (an async headless browser) is then deployed to physically visit the URLs, rendering the DOM and utilizing BeautifulSoup4 to strip out navigation headers, footers, and scripts, leaving only the pure semantic text payload.

4. AI Forensic Engine & Fallback Hierarchy

The extracted text payloads are batched and routed to the Generative AI Cluster. The system prompt configures the AI to act as a highly specialized Forensic Accountant governed by a core directive: "Extreme Benefit of the Doubt." The AI will assume the user's Excel sheet is correct unless it discovers definitive, conflicting corporate evidence.

The Fallback Fault-Tolerance Sequence

To guarantee enterprise-level high availability (99.9% uptime) and bypass rigid API rate-limiting restrictions, the backend implements a cascading fallback loop using the google-genai SDK. If a model times out or rejects the payload, the system instantly catches the exception and routes the request to the next tier:

  • Tier 1 (Primary): gemini-3.6-flash — Maximum reasoning capability and speed.
  • Tier 2 (Secondary): gemini-3.5-flash — High reasoning redundancy.
  • Tier 3 (Tertiary): gemini-3.1-flash — Stable legacy fallback.
  • Tier 4 (Safety): gemini-3.5-flash-lite — Lightweight, high-throughput model guaranteed to execute if heavy models are throttled.

5. Real-Time Telemetry & Visualization

Historically, heavy AI processing jobs are black boxes that force the user to wait blindly. This architecture solves that via dual-layer telemetry:

  • WebSocket Data Streaming: As the AI cluster parses chunks and resolves entities, the FastAPI backend streams entity_result packets through an active WebSocket connection (ws:// protocol).
  • Physics-Based UI Rendering: The frontend JavaScript engine intercepts these packets and pipes them into a vis-network canvas. The browser dynamically computes a physics-based, repulsive-node Network Graph in real-time. Verified matches spawn as green nodes linked directly to the central Parent Company, while rejected entities spawn as dashed red nodes.

6. Deployment & Setup Specifications

The system is designed to be highly portable. It requires Python 3.10+ and a standard .env file for secrets management.

Environment Variables Required

GEMINI_API_KEY=your_gemini_api_key_here
SERPER_API_KEY=your_serper_api_key_here

Environment Instantiation

# 1. Initialize Virtual Environment
python -m venv venv
source venv/bin/activate  # On Windows: .\venv\Scripts\activate

# 2. Install Core Dependencies
pip install fastapi uvicorn google-genai playwright beautifulsoup4 openpyxl pandas python-multipart

# 3. Provision Headless Browser Binaries
playwright install chromium

# 4. Boot the Uvicorn Server
python main.py

Upon execution, the server binds to 0.0.0.0:8000 and serves the client interface directly.
